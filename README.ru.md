# ayla-tools-compact

[English](README.md) · **Русский**

Компактные однострочные строки инструментов для [Pi](https://pi.dev) — расширение,
которое меняет только отрисовку `bash`, `read`, `grep`, `find` и `ls`.

> **Статус: публичная бета (`0.1.0-beta.1`).** Проверено на Pi `1.3.0`. Что именно
> покрывает это утверждение, а что нет — в разделе [Совместимость](#совместимость).

Вместо полноширинного цветного блока на каждый вызов инструмента — одна строка: глиф
состояния, имя инструмента, аргументы и полезная часть вывода.

```text
✓ $ pwd && whoami && date 0.0s
  /Users/example
  example
  Tue Oct 19 02:38:11 UTC 2026
```

```text
· grep /renderResult/ --glob extensions/*.ts
  extensions/index.ts: renderResult(result, options, theme, context) {
  extensions/index.ts: return lines((width: number) => {
  … +7 lines · ctrl+o
```

В свёрнутом виде показываются 5 строк вывода (9 для упавшего вызова), `ctrl+o`
раскрывает до 400 строк. У шелла в заголовке есть длительность, а в выводе — **хвост**,
где обычно лежат ошибки; у файловых инструментов показывается **начало**.

## Что меняется, а что нет

| | |
|---|---|
| Меняется | Как рисуются вызовы и результаты `bash`, `read`, `grep`, `find`, `ls`. |
| Не меняется | Имена инструментов, описания, схемы параметров, исполнение, права, содержимое результатов, хранение сессии. |
| Не покрыто | `edit`, `write` и все остальные инструменты сохраняют штатную отрисовку Pi. |

Расширение регистрирует определения инструментов с теми же публичными именами, что и
встроенные в Pi, и переиспользует встроенные определения для схемы и исполнения. Оно
сознательно не переписывает сами инструменты: работают те же кодовые пути, то же
разрешение `cwd` и те же результаты ошибок. Реестр инструментов Pi позволяет
зарегистрированному определению с тем же именем заменить встроенное — это единственный
используемый механизм.

## Установка

Нужен работающий Pi. У самого расширения нет runtime-зависимостей;
`@earendil-works/pi-coding-agent` и `@earendil-works/pi-tui` — поставляемые хостом peer'ы.

```bash
# npm (после публикации беты)
pi install npm:ayla-tools-compact@0.1.0-beta.1

# git (в реальном использовании фиксируйте commit или tag)
pi install git:github.com/kekma-dot/ayla-tools-compact@<commit>

# локальный checkout
pi install ./ayla-tools-compact
```

Попробовать на одну сессию, не добавляя в настройки:

```bash
pi -e npm:ayla-tools-compact@0.1.0-beta.1
```

`pi list` показывает настроенные пакеты. Личная установка попадает в
`~/.pi/agent/settings.json`; `--local` пишет в `.pi/settings.json`, который Pi читает
только после выдачи доверия проекту.

## Отключение, фильтрация, удаление

```bash
PI_GLAM_TOOLS=0 pi                 # один запуск без отрисовки этого расширения
pi config                          # включить/выключить расширение пакета интерактивно
pi remove npm:ayla-tools-compact   # убрать декларацию пакета
```

Переменная окружения называется `PI_GLAM_TOOLS` ради совместимости с прежними
установками и намеренно не переименовывается; `PI_GLAM_TOOLS=0` не регистрирует ни
одного инструмента, поэтому остаётся штатная отрисовка Pi. Чтобы оставить пакет
установленным, но не загружать его расширения, отфильтруйте его в настройках:

```json
{
  "packages": [
    { "source": "npm:ayla-tools-compact", "extensions": [] }
  ]
}
```

После удаления пакета перезапустите Pi, чтобы вернулись встроенные renderer'ы.

## Детали поведения

| Случай | Отрисовка |
|---|---|
| Свёрнуто | 5 строк вывода и `… +N lines · ctrl+o` — перед хвостом, после начала. |
| Раскрыто (`ctrl+o`) | До 400 строк; остаток по-прежнему показывается числом. |
| Ошибка (`isError`) | 9 строк превью и глиф `✗`; у шелла виден хвост с ошибкой. |
| Шелл (`bash`) | Длительность (`0.1s`, от старта исполнения до финального результата), хвост вывода. |
| `read` | `путь:от-до` при использовании `offset`/`limit` и счётчик `lines`. |
| `grep`, `find`, `ls` | Сводка аргументов и счётчик `matches`/`entries`. |
| Широкий вывод | Каждая строка обрезается по ширине терминала; переносов внутри строки нет. |
| ANSI-цвет в выводе | Вырезается, чтобы чужой цвет не ломал отступ и ширину. |
| Табуляция | Рисуется как два пробела. |
| Управляющие символы | Заменяются пробелами до отрисовки, включая многострочную команду шелла. |
| Пустой вывод | Строк тела нет. |

Отрисовка используется в интерактивном транскрипте и в HTML-экспорте транскрипта Pi.
В неинтерактивных режимах (`--print`, RPC) строк инструментов нет, поэтому кроме
регистрации расширение там ни на что не влияет.

## Безопасность

- Расширение не открывает сокетов, не запускает собственных процессов и читает ровно
  одну переменную окружения (`PI_GLAM_TOOLS`).
- Исполнение делегируется встроенным определениям Pi, поэтому правила прав,
  подтверждения, изоляция и форма результатов не меняются.
- Нет телеметрии, фоновых таймеров и записей вне обычного хранилища сессий Pi.
- Замена встроенных имён видна любому расширению, которое смотрит на определения
  инструментов.

## Совместимость

`peerDependencies` объявляют `"*"` для пакетов хоста, как требует документация пакетов
Pi; это контракт подстановки модулей, **а не** гарантия совместимости.

Проверено: `@earendil-works/pi-coding-agent` `1.3.0` и `@earendil-works/pi-tui` `1.3.0`,
загрузка через настоящий `DefaultResourceLoader` Pi и реальный `AgentSession`, на macOS
с Node 25.9.0. Другие версии Pi не проверялись: расширение опирается на
`pi.registerTool`, `renderShell: "self"`,
`renderCall`/`renderResult` и семантику состояния `ToolRenderContext`. Если хост изменит
их, пакет нужно перепроверить и выпустить заново.

## Ограничения

- Переоформлены только пять инструментов; `edit` и `write` вне области.
- Размеры превью, потолок раскрытия и глифы заданы в исходнике; настроек нет, изменение
  требует правки или форка.
- Счётчики считают строки вывода, а не смысловые совпадения.
- Цветной вывод теряет цвет, потому что ANSI-последовательности вырезаются.
- Отрисовка — функция терминала: она не уменьшает число токенов, отправляемых модели.
- Бета: отрисовка опирается на внутренности хоста, которые публичны, но молоды.

## Разработка

Для разработки нужен Node 22.19+ (в CI — Node 24); опубликованное расширение
загружается штатным TypeScript-загрузчиком Pi и собственных требований к Node не добавляет.

```bash
npm ci
npm run check   # TypeScript против точных деклараций Pi 1.3.0
npm test        # node:test, без тестового фреймворка
```

Набор тестов намеренно небольшой и должен падать при дрейфе контракта отрисовки:

- `tests/registration.test.mjs` — упаковывает пакет через `npm pack`, распаковывает
  реальный артефакт, загружает его настоящим `DefaultResourceLoader` Pi, проверяет пять
  зарегистрированных определений и их `renderShell: "self"`, проверяет, что реальный
  `AgentSession` разрешает эти определения вместо встроенных, и что `PI_GLAM_TOOLS=0`
  не регистрирует ничего. Там же проверяется состав tarball: без зависимостей и тестов.
- `tests/rendering.test.mjs` — прогоняет настоящие renderer'ы: однострочные заголовки,
  границы превью (5 / 9 / 400), хвост против начала, счётчики и длительность, частичные
  результаты, обновление аргументов, замена управляющих символов, вырезание ANSI и
  безопасность ширины для CJK, эмодзи и комбинируемых символов.
- `tests/delegation.test.mjs` — исполняет через зарегистрированные определения во
  временном каталоге: передачу `cwd`, контекст хоста (`PI_SESSION_ID`), ошибки с кодом
  выхода, относительные пути для `read`/`ls` и переиспользование делегата.

CI настроен выполнять `npm ci`, `npm run check` и `npm test` на Ubuntu и macOS с Node
24. Локальная проверка шла на Node 25.9.0; набору нужны только `node:test` и штатный
загрузчик Pi, которые от версии Node в этом диапазоне не зависят.

## Удаление и откат

`pi remove <source>` (или удаление записи из настроек, или `PI_GLAM_TOOLS=0`) возвращает
штатную отрисовку Pi. Пакет ничего не пишет вне обычного каталога пакетов Pi, поэтому
откат не требует уборки.
